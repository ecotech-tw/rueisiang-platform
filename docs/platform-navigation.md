# 平台導覽與使用流程

本文件說明平台有哪幾個入口、各自服務誰、頁面怎麼分層，以及新的系統（例如會計）要放在哪裡。
導覽的程式來源是 `apps/portal/src/shell/nav.ts`、`apps/portal/src/routes/hr/HrLayout.tsx` 與
`apps/hr/src/App.tsx`；兩邊說法不同時以程式為準。HRIS 內部的頁面階層另見
[`hr-navigation-prd.md`](./hr-navigation-prd.md)。

## 1. 三個入口

| 入口 | 網址 | 給誰 | 怎麼進 |
|---|---|---|---|
| 營運平台 | `platform.rueisiang.com` | 總部同仁：客服、倉管、營運、管理者 | Google 帳號或邀請時設定的 email／密碼（都是邀請制），側邊選單 |
| HRIS | 同一個 portal 的 `/hr` | 人資與管理者 | 側邊選單左下角的 HRIS 入口（`SystemSwitcher`），有任一 HR 讀取權限才出現 |
| 員工自助 | `hr.rueisiang.com`（`apps/hr`） | 每一位員工與支援人員 | 手機、LINE 內建瀏覽器 |

三個入口共用一個 API、一份 schema、一套權限。差別只在**用的人與節奏**：營運平台是每天、
HRIS 是每月、員工自助是每個人自己的事。HRIS 從側邊選單拆出去、改成獨立的上方導覽，
就是因為它的使用者與節奏跟營運平台不一樣。

## 3. 主要流程

頁面是為了流程存在的。下面每一條是一件「有人要從頭做到尾」的事，箭頭跨越的入口就是
兩個系統交接資料的地方。

```text
每日營收     CYBERBIZ／蝦皮／momo ─(報表執行)→ report_payout_daily、銷售月表 → 營運統計
客戶         CYBERBIZ webhook／同步 → 客戶列表 → 標籤 → 操作紀錄
庫存         品項列表 → SKU 對應 → 倉位地圖／庫存管理（官網訂單自動扣、蝦皮人工補扣）
出勤到薪資   員工自助打卡、請假、加班 → HRIS 申請與審核 → 出勤紀錄 → 薪資結算 → 員工自助薪資袋
小香         LINE 對話 → 查詢、HR 申請草稿 → HRIS 申請與審核
```

**每日營收**與**出勤到薪資**是兩條會流進會計的線：前者是錢進來，後者是錢出去。

## 4. 什麼時候該加一個入口

頁面多不是問題，**入口多**才是。判斷順序：

1. **是同一件事的另一個面向** → 放在現有頁面的分頁、區塊或對話框。報表執行把四種報表收進一頁、
   「新增客人」是客戶列表上的對話框而不是一個選單項，都是這一條。
2. **是同一群人、同一個節奏的另一件事** → 在現有大項底下加一個入口。
3. **使用者或節奏都不一樣，而且自己有一串流程** → 開一個獨立系統，從 `SystemSwitcher` 進去，
   用自己的上方導覽。HRIS 是唯一的先例。

側邊選單只放「要導覽過去的地方」；只是一個動作的，留在它所屬的頁面上。

## 5. 會計放在哪裡

### 建議：比照 HRIS，做成第二個獨立系統

會計符合上一節的第 3 條：

- **使用者不同**：會計或老闆，不是每天操作客戶與庫存的同仁。
- **節奏不同**：以帳期（月）為單位，有結帳與鎖帳；跟 HRIS 的薪資結算同一種節奏。
- **自己有一串流程**：匯入來源 → 對帳 → 調整 → 結帳 → 報表，不是一兩個頁面。

塞進營運平台的側邊選單會變成第八個大項、再多五六個入口，而且使用者大多用不到其他七項。
獨立系統的作法 HRIS 已經走過一次：`SystemSwitcher` 改成能列多個系統、會計有自己的 layout
與上方導覽、權限決定看不看得到入口。不用新的部署單位，仍然是同一個 portal。

### 會計吃哪些既有資料

| 來源 | 現有的表 | 在會計裡是什麼 | 現況的缺口 |
|---|---|---|---|
| 每日出金 | `report_payout_daily`（店別 × 營業日 × 金額） | 收入、應收 | 只有一個出金金額欄位，手續費與退款沒有拆開 |
| 商品銷售 | `report_item_sales_monthly`、`report_bundle_sales_monthly`、momo 快照 | 營收明細 | 以月為單位 |
| 薪資 | `hr_payroll_runs`、`hr_payslips`、`hr_payslip_lines`（已結帳） | 薪資費用、代扣勞健保 | 只有結帳後的批次才能當作入帳依據 |
| 品項 | `items.list_price` | — | **沒有成本欄位**，算不出毛利 |
| 庫存 | `wms_items` | 存貨 | 只有數量，沒有金額 |

會計只讀這些表，不回寫。來源是「已結帳」的才入帳，跟薪資結算靠已結帳批次鎖住資料是同一個道理。

### 資料層的約束

- 時間照 [`database-conventions.md`](./database-conventions.md)；帳期用「台北的日期」切，換成 UTC
  起訖用 `taipeiMidnightUtc`。
- 金額存 INTEGER，但**既有的兩邊單位不同**：報表（`report_payout_daily.payout_amount` 等）存元，
  薪資（`*_minor` 欄位）存分，也就是元 × 100；`hr-payroll-calculation.ts` 讀出金時就是乘 100 換成分。
  會計表建議跟薪資一樣存分、欄位名稱帶 `_minor`，因為代扣勞健保會有小數；從報表讀進來時乘 100。
- 會計表的外鍵用 `ON DELETE RESTRICT`。既有的表有 27 個 CASCADE（父表包含 `users`、`items`、
  `report_runs`），會計的分錄不能因為刪了一筆來源就跟著消失。
- 已結帳的帳期用 trigger 擋修改，作法照薪資結算的守門 trigger。

### 開工前要先決定的事

1. **範圍**：是管理用的損益與收支（看每家店賺多少），還是要出正式帳（傳票、總帳、試算表，
   交給會計師報稅）。前者用既有報表加成本就做得出來；後者需要科目表與複式分錄，是另一個量級。
2. **成本從哪裡來**：品項的進貨成本由誰維護、多久更新一次。沒有它，損益只算得到營收。
3. **跟外部會計軟體的關係**：如果會計師已經用自己的軟體，平台只要匯出，不需要在平台裡結帳。
