# 執行 PRD：出勤紀錄與打卡驗證

## 1. 目的

提供正式員工的伺服器時間打卡、出勤紀錄、辦公地點驗證與補打卡流程。打卡是出勤事實的保存，不直接推導薪資；薪資使用核准加班、人工工時與假勤資料。

## 2. 導覽

```text
員工入口：HR App → 打卡／出勤日曆／補打卡
管理入口：HRIS → 出勤管理 → 出勤紀錄
```

## 3. 打卡規則

- 打卡時間一律使用伺服器時間，不採信使用者裝置時間。
- 只有對應活動 `hr_employments`（`archived_at IS NULL`）的使用者可以新增打卡；封存不刪除既有事件。
- 使用者可以在所有有效辦公地點打卡，不限於當日排班地點。
- 沒有排班也可以打卡；排班不是打卡必要條件。
- 同一人同一打卡動作使用 idempotency key，重送不產生重複事件。
- 地理位置要求依辦公地點設定驗證；定位無法取得時依該地點規則回應，不由前端繞過。
- 打卡成功後保存事件與驗證結果；驗證異常不代表打卡失敗。

## 4. 排班班別時段驗證

排班制員工的預期時段由排班月曆所選班別提供：

- 上班時間與下班時間
- 休息時間
- 標準計薪工時

辦公位置不提供工作時段，只提供可打卡地理範圍。一般辦公員工沒有排班班別時，不以辦公位置名稱推導上下班時間。

打卡驗證依當日已發布排班班別比對：

```text
提前打卡 → 提前提示
上班遲到 → 遲到提示
提前離開 → 早退提示
超過下班 → 超時提示
休息日打卡 → 休息日提示
```

打卡時間異常只作出勤提示，不自動扣薪、不自動增加薪資，也不取代核准的加班申請。

## 5. 出勤紀錄管理 UI

```text
日期：[2026-08-01～2026-08-31]
員工：[全部 ▾]  工作地點：[全部 ▾]  狀態：[全部 ▾]

日期        員工      地點    預期時段       實際打卡       狀態
08/05       王小明    台北店  10:00～19:00   09:52～19:10   超時
08/06       李小華    桃園店  11:00～20:00   11:15～20:00   遲到
```

列表支援：

- 月份／日期區間
- 員工／員工編號
- 實際打卡地點
- 排班地點
- 正常、遲到、早退、超時、休息日與地點不一致
- 分頁與內部捲動

展開紀錄可以查看：

- 伺服器時間
- 實際地點與定位驗證結果
- 預期上下班時段
- 打卡來源
- 補打卡前後資料與核准紀錄

## 6. 補打卡

```text
員工提出補打卡
→ 日期、上班／下班時間、原因
→ 直屬主管核准
→ 建立正式出勤紀錄
```

- 沒有可用主管時，由全平台 HR 管理者代為核准並填寫原因。
- 申請人不可核准自己的申請。
- HR 可以代員工建立或修正，需保存代登人員、時間與原因。
- 未核准補打卡不更新正式出勤結果，只列為出勤提醒。
- 核准後保存原事件、修正後事件、申請人、核准人與時間。
- 補打卡不自動產生加班費。

## 7. 薪資關係

- 打卡時間提前、遲到、早退、超時只作提醒，不影響薪資。
- 排班據點是每日工作安排參考；打卡位置只依員工授權的辦公位置與 GPS 範圍判斷，不因與排班據點不同而拒絕打卡。
- 加班必須另外申請並經核准，不能以超時打卡代替。
- 時薪工時由月底人工登記，不由打卡事件自動產生。
- 假勤由月度資料登記人工輸入，依月度登記的扣款金額處理。

## 8. 權限與隱私

- 員工只能查看自己的打卡與補打卡資料。
- 主管只能查看其核准範圍內的申請；完整出勤管理由全平台 HR 管理者執行。
- 完整打卡地點與定位驗證資料只提供全平台 HR 管理者。
- 薪資、勞健保與完整打卡明細不得透過一般員工列表或非授權 API 回傳。

## 9. 歷史與稽核

- 正式出勤事件採 append-only；修正以新事件／補打卡紀錄保存，不覆寫歷史。
- 保存建立者、建立時間、來源、核准者、核准時間與必要的原因。
- 已結帳期間的出勤資料不得直接修改；需要影響薪資時使用薪資調整。所有事件與補打卡都保留原 `employmentId`，員工封存不改寫出勤歷史。

## 10. 不包含

- 完整請假申請、簽核與假別額度；見月度人工假勤 PRD。
- 以打卡自動產生時薪工時。
- 以超時打卡自動計算加班。
- 指定日期特殊營業時段覆寫。
