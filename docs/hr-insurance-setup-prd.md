# 執行 PRD：員工勞保／健保設定

## 1. 目的

在既有員工與任職資料下，讓全平台 HR 管理者為指定任職建立勞保／健保的加保、退保與投保級距版本。資料依任職與有效期間保存，不覆寫歷史。

```text
hr_employments 1 ─── N hr_insurance_versions
                         ├─ labor
                         └─ health
```

姓名、Email 與 User 狀態仍從 `users` 讀取；投保資料不進一般員工列表。

## 2. 導覽位置

勞保／健保不建立獨立 Sidebar 項目，也不放入一般員工列表的欄位。

```text
HRIS
└─ 薪資
   └─ 勞健保管理
```

勞健保跟敘薪一樣會進薪資計算，所以放在薪資底下，不放在員工管理。「勞健保管理」提供全體員工的投保總覽與版本異動入口，勞保與健保一起編輯、一起存成版本；單一員工的完整投保脈絡仍在員工內頁的「勞健保 Accordion」唯讀查看。

每位員工以穩定 `employmentId` 管理投保資料；員工封存不刪除既有投保版本，新的投保版本仍由保險自身的有效期間規則驗證。

## 3. 權限

- 查看勞保／健保：全平台 HR 管理者。
- 新增加保、退保或級距版本：全平台 HR 管理者。
- 一般 HR 員工讀取權限不會自動包含投保明細。
- 投保金額、眷屬人數與來源不顯示在一般員工列表或非 HR 管理者的 API 回應中。

## 4. 員工內頁 UI

### 勞健保 Accordion

Accordion 展開後分成兩張摘要卡：

#### 勞保

顯示：

- 狀態：加保中／已退保
- 目前投保金額
- 生效期間
- 級距年度
- 來源：官方／人工
- 版本異動請回到「勞健保管理」建立新版本

#### 健保

顯示：

- 狀態：加保中／已退保
- 目前投保金額
- 眷屬人數
- 生效期間
- 級距年度
- 來源：官方／人工
- 版本異動請回到「勞健保管理」建立新版本

摘要下方顯示該任職的歷史表：

| 種類 | 狀態 | 生效期間 | 投保金額 | 眷屬 | 級距來源 |
|---|---|---|---:|---:|---|
| 勞保 | 加保中 | 2026-08-01～目前 | NT$ 45,800 | — | 官方 2026 |
| 健保 | 加保中 | 2026-08-01～目前 | NT$ 45,800 | 2 | 官方 2026 |

歷史版本不可直接編輯或刪除，只能新增後續版本。

## 5. 新增投保版本 Dialog

從「新增勞保版本」或「新增健保版本」開啟同一套表單，進入時鎖定種類。

### 基本欄位

| 欄位 | 勞保 | 健保 | 規則 |
|---|---:|---:|---|
| 狀態 | 是 | 是 | 加保／變更級距、退保 |
| 生效日 | 是 | 是 | 依保險版本的有效期間與薪資結算規則驗證，不以已移除的任職日期判定 |
| 迄日（不含） | 否 | 否 | 留空代表持續有效 |
| 級距年度 | 是 | 是 | 預設目前年度 |
| 實際月薪 | 加保時必填 | 加保時必填 | 由薪資項目投保旗標自動加總，可由 HR 調整並留下備註 |
| 官方投保級距 | 加保時必填 | 加保時必填 | 從官方資料選擇 |
| 眷屬人數 | 不顯示 | 是 | 0～3 人 |
| 備註 | 否 | 否 | 人工覆寫時必填 |

退保時：

- 不要求實際月薪與級距。
- 投保金額保存為 0。
- 只需要狀態、生效日與備註。

## 6. 官方級距與年度費率同步

官方級距與費率不採即時查詢，也不讓薪資結算依賴外部網站即時回應。每年由全平台 HR 管理者在「薪資管理／制度設定／勞健保費率」按下「同步最新官方資料」。

同步流程：

```text
按下同步最新官方資料
→ 後端抓取官方公開資料／API
→ 顯示勞保與健保的年度差異
→ HR 確認啟用
→ 保存不可變更的年度費率版本
```

- 系統保存年度、適用起日、資料來源、抓取時間與內容雜湊。
- 同一年度重複同步不建立重複版本；若官方資料有變更，建立新來源版本並要求確認。
- 薪資結算只使用已啟用且保存於資料庫的費率版本。
- 官方來源無法取得時，保留目前已啟用版本並顯示同步失敗提醒。
- 同步失敗不阻擋薪資作業；全平台 HR 管理者可以手動編輯更新費率或級距，並留下來源／備註與操作紀錄。
- 手動更新的資料標示為人工來源，不冒充官方同步結果。

員工投保版本設定時：

1. 系統從當時有效的薪資項目，加總標記為「納入投保基礎」的項目。
2. HR 檢視實際月薪與計入項目。
3. 系統使用已啟用年度級距依薪資範圍預選投保金額。
4. HR 可以確認或選擇其他官方級距。
5. 若調整實際月薪或人工選擇投保金額，必須留下備註。
6. 表單顯示實際月薪、計入項目、投保金額、級距年度、資料來源與抓取時間。

若需要人工覆寫，HR 必須填寫投保金額與備註；來源 URL 非必填，資料標示為人工來源。

## 7. 版本規則

- 加保、退保與級距變更一律新增版本。
- 同一任職、同一保險種類的有效期間不可重疊。
- `validTo` 是不再適用的第一天，採 `[validFrom, validTo)`。
- 新版本生效日到達時，前一個開放版本自動關閉。
- 歷史版本不可覆寫、刪除或重新計算。
- 薪資調整不自動改變投保級距；需要 HR 明確建立新的投保版本。
- 薪資項目變更後，系統提示 HR 檢查是否需要建立新的投保版本，不直接修改歷史投保資料。

例如：

```text
勞保版本 A：2026-01-01～2026-08-01
勞保版本 B：2026-08-01～目前
```

## 8. 薪資結算關係

本頁的責任是保存投保狀態、投保金額、級距年度與來源；薪資結算依計算月份選取當時有效版本。

員工扣款、公司負擔、眷屬保費與特殊費率不在員工投保表單內由 HR 手動輸入。正常情況由薪資引擎依已啟用且保存的法定費率版本計算；若薪資結算時資料缺漏，HR 可在該期薪資批次手動輸入員工扣款。

勞退與勞保／健保分開管理：

```text
薪資管理／制度設定
├─ 勞保／健保費率：年度官方資料同步
└─ 勞退提繳：獨立的公司提繳設定
```

勞退設定不得混入勞保投保金額，也不使用勞保級距同步結果。

若目前年度費率尚未同步，UI 顯示：

> 尚未同步本年度官方費率，可手動更新費率或在薪資批次輸入員工扣款。同步失敗不阻擋薪資作業。

預估員工負擔金額使用已啟用的費率版本計算；正式扣款仍以薪資結算當期有效版本為準。

## 9. 例外與錯誤

- `employmentId` 不存在或已封存且操作不符合該頁規則：拒絕保存；生效日由保險版本自身的期間規則驗證。
- 同一種類的有效期間重疊：拒絕保存。
- 加保但沒有有效投保金額：拒絕保存。
- 健保眷屬人數不在 0～3：拒絕保存。
- 官方資料讀取失敗：顯示錯誤，允許全平台 HR 管理者手動更新並留下來源／備註。
- 同步失敗或費率缺漏只顯示提醒，不禁止薪資試算或結帳；若未能自動計算，薪資批次可手動輸入員工扣款並記錄原因。
- 已退保版本不可直接重新編輯，重新加保需新增版本。
- 所有新增版本均保留建立者、建立時間、來源與備註。

## 10. UI 設計要求

- 「勞健保管理」提供全體員工投保總覽，顯示員工、任職狀態、勞保／健保狀態、投保金額、眷屬與資料提醒。
- 點擊員工後顯示勞保／健保版本、實際投保基礎、級距、眷屬、來源、生效期間、人工備註與歷史版本。
- 員工內頁保留勞健保 Accordion，顯示單一員工的完整歷史。
- 依設計規範使用既有 Panel、Dialog、Data Table 與狀態膠囊。
- 不在一般員工列表顯示投保金額或眷屬資料。
- Dialog 內使用一般表單欄位；級距清單使用下拉選單。
- 「薪資管理／制度設定／勞健保費率」提供「同步最新官方資料」按鈕、年度版本狀態與上次同步時間。
- 同步後先顯示差異，確認後才啟用新費率。
- 官方來源資訊使用輔助文字呈現，不使用不可追溯的前端常數。
- 手機版歷史表使用 `data-label`。
- 成功後關閉 Dialog、重新載入摘要與歷史表，並顯示操作成功訊息。

## 11. UI 決策

1. 官方級距由系統依實際月薪預選，HR 可以調整為其他官方級距。
2. 健保眷屬人數允許 0～3 人。
3. 人工覆寫的來源 URL 非必填，但必須留下備註；資料仍標示為人工來源。
4. 退保原因非必填，但可以填寫備註。
5. 勞保／健保摘要卡顯示預估員工負擔金額；正式金額必須依有效費率版本計算，不由前端自行推算。
6. 官方費率每年由 HR 管理者按「同步最新官方資料」取得，不依賴即時外部查詢；同步失敗時可手動更新，不阻擋薪資作業。
7. 手動更新的費率與級距標示人工來源並保留備註與稽核紀錄。
8. 勞退獨立於勞保／健保費率管理。
