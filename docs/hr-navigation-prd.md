# 執行 PRD：HRIS 導覽與頁面階層

## 1. 設計目標

HRIS 以管理者的日常工作流程設計，不以資料表或內部 schema 拆成大量功能入口。

管理者主要有三種工作：

```text
人事建檔：建立員工、任職、勞健保與敘薪
每月作業：排班、查看出勤異常、登記假勤與時薪工時、薪資試算與結帳
規則設定：工作地點、出勤規則、特殊上班日與獎金規則
```

因此 Sidebar 只保留四個主要入口，細項放在 Header Tab、頁面區塊或 Dialog。

## 3. 建議的 Sidebar 與 Header

```text
Sidebar
┌──────────────────────┐
│ HRIS                 │
│  員工管理             │
│  出勤管理             │
│  排班管理             │
│  薪資                 │
└──────────────────────┘
```

### 員工管理

```text
員工子選單： [員工列表] [支援人員]
```

支援人員是可排班、可計薪的外部人力，不建立平台帳號、`user` relation 或員工任職資料。管理入口放在員工子選單只是為了讓人事建檔集中；支援人員的排班使用仍在「排班／排班月曆」，薪資版本則在「薪資／敘薪管理」的支援人員區塊。只能停用、不能刪除，以保留歷史排班、薪資版本與薪資快照。

員工內頁只保留勞健保 Accordion，作為單一員工的完整脈絡檢視；投保版本異動在「薪資／勞健保管理」。

### 出勤管理

```text
Header Tabs： [出勤紀錄] [出勤範圍管理] [據點管理] [特殊上班日]
```

特殊上班日屬於日期與出勤規則；其中的薪資倍率、固定每小時金額與補貼設定，會提供給薪資結算使用。加班規則則放在據點管理中，支援行政人員的法定計算與指定人員的固定每小時金額。

出勤異常與補打卡放在出勤紀錄的篩選、異常區塊或操作入口，不再新增獨立 Sidebar 項目。

### 排班管理

```text
Header Tabs： [排班月曆] [班別管理]
```

班別管理依營運據點建立早班、晚班與假日班，設定上下班時間、休息時間與計薪工時；出勤範圍管理則在排班模式下設定員工約定的每月休假天數與可打卡辦公位置。排班月曆負責設定特定日期的工作地點與班別，儲存即直接發布；鎖定／開鎖是排班月曆的頁面操作。

排班月曆的主要操作是：

```text
（選用）篩選據點 → 快速排班或點日期 → 儲存（直接發布）
```

### 薪資

```text
Header Tabs： [敘薪管理] [勞健保管理] [獎金管理] [制度設定] [薪資結算]

薪資結算內的「月度資料登記」集中輸入時薪工時與假勤，不在出勤管理建立第二個編輯入口。
```

「敘薪管理」以正式員工／支援人員兩個平行區塊管理薪資版本；正式員工沿用任職關聯，支援人員以獨立主檔與薪資版本管理。支援人員不出現在員工內頁，也不與 `user` 建立 relation。「勞健保管理」提供全體員工投保總覽，勞保與健保在同一個 Dialog 一起加保、變更或退保；「制度設定」負責年度勞健保費率同步與獨立的勞退提繳設定；「薪資結算」負責試算、檢查異常與結帳。特殊上班日已歸入出勤管理。

## 4. HRIS 概覽首頁

首頁不做複雜報表，提供四張待辦卡：

```text
┌─────────────────────────────────────────────┐
│ HRIS 概覽                                    │
├──────────────┬──────────────┬───────────────┤
│ 出勤異常      │ 排班待發布    │ 投保資料缺漏   │
│ 12 筆          │ 2 個據點      │ 3 位員工      │
│ [查看]         │ [前往排班]    │ [前往勞健保]  │
├──────────────┴──────────────┴───────────────┤
│ 本月薪資                                        │
│ [開始試算]                                      │
└─────────────────────────────────────────────┘
```

首頁只呈現需要處理的事情，不複製各功能的完整資料表。出勤異常、排班待發布與本月薪資以目前月份／目前薪資期間計算；投保資料提醒以目前有效員工計算。卡片只顯示數量與處理入口，不直接顯示個人薪資或保險敏感明細。

## 5. 每月管理流程

```mermaid
flowchart LR
  A[排班月曆] --> B[出勤紀錄]
  B --> C[檢查出勤異常]
  C --> D[月底登記假勤與時薪工時]
  D --> E[薪資試算]
  E --> F[查看異常提醒]
  F --> G[薪資結帳]
```

薪資流程簡化為：

```text
月底登記假勤與時薪工時 → 試算 → 查看異常提醒 → 修正資料並重試算 → 結帳
```

異常提醒不阻擋試算，但結帳前必須顯示未處理異常數量與明細入口。只有薪資無法正確計算的客觀資料錯誤才阻擋結帳，例如沒有薪資基準、時薪工時未登記且未標記無工時，或存在未完成的資料一致性錯誤。勞健保同步失敗只提醒，仍可手動更新。

## 6. 核心薪資規則

- 支援人員可以排班。
- 班別由據點管理；同一人同一天可以安排一個或多個不重疊班別。
- 特殊上班日薪資取代當日底薪。
- 特殊上班日固定金額以每小時計算。
- 月薪制員工入職／離職當月按固定 30 日制比例計算，立即適用於未結帳期間；已結帳歷史不重算。
- 加班費以 0.5 小時為計算單位。
- 日薪制員工依已發布排班日期計薪。
- 時薪員工每月底由 HR 登記實際工作日期與工時（以 0.5 小時為單位），不由排班或打卡自動產生。
- 獎金不限制只能發給排班人員；薪資結算時以異常提醒通知管理者。
- 實際打卡地點與排班地點不同時列為薪資結算異常；修正排班後重新試算。
- 薪資流程為試算後直接結帳，不增加額外核准階段。
- 勞健保官方費率一年同步一次，由 HR 管理者按鈕觸發抓取並確認啟用；薪資結算不依賴即時外部查詢。
- 薪資結算計算員工勞保／健保負擔，不顯示公司負擔。
- 勞退制度獨立於勞保／健保費率管理。
- 手動補打卡需要主管核准。
- 薪資結帳後發現錯誤，建立薪資調整，不直接修改已結帳結果；例如 8 月調整於 9 月生效。
- 假勤以 0.5 小時為單位，記錄給薪比例（例如 100%、50%、0%）與 HR 人工輸入的扣款金額。
- 特殊上班日同一員工同一天只能套用一個規則，工時來源可由規則自行設定；缺少工時資料時列為異常。
- 業績來源由 policy 設定，可調整，不增加額外凍結操作；結帳時保存實際使用的 policy 與業績快照。

## 7. 導覽規則

- Sidebar 只放主要工作領域，不放每個資料表或操作。
- Header Tab 只放同一領域的平行頁面。
- 員工內頁 Accordion 只放單一員工的詳細資料，不承載資料異動操作；異動從對應的管理頁進入。
- Dialog 用於建立、變更與新增版本。
- 待處理異常集中顯示入口，但不重複建立另一套資料管理頁。
- 投保金額、眷屬、薪資與完整打卡明細只對具備相應權限的管理者顯示。
- 完整打卡紀錄的主入口是「出勤管理／出勤紀錄」；員工內頁只提供依員工篩選的唯讀捷徑。
