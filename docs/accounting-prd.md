# 執行 PRD：會計（內帳）

會計系統放在哪裡、為什麼做成獨立系統，見 [`platform-navigation.md`](./platform-navigation.md) 第 5 節。
本文件說明它要做什麼、資料怎麼存、第一步做哪些。

## 1. 範圍

**內帳**：公司自己看錢用的帳，不是交給會計事務所報稅的正式帳。目標是回答「這個月、這家店，
進來多少、出去多少」。

- **記什麼**：只要有發票、可以報帳的支出都記，從通路進貨到日常備品。
- **不做什麼**：科目表、傳票、複式分錄、試算表。那是正式帳，由會計事務所做。
- **跟事務所的關係**：平台提供匯出（Excel）；格式等問過事務所再定，所以匯出欄位集中定義在一處，
  之後改格式只改那裡。
- **商品成本**：每一種商品各花多少錢進貨（一盒餅進價 60、賣 100，成本就是 60）。內帳只要知道
  「這個月進貨總共花多少」就夠，所以第一版**不做**逐項商品成本；要算單一商品毛利時再加。

## 2. 支出：一本帳、兩種付款人

所有支出都是同一種東西——一張有發票的支出單。差別只在**誰先付了錢**：

| 付款人 | 例子 | 誰登記 | 在哪裡登記 | 之後 |
|---|---|---|---|---|
| 員工代墊（報公帳） | 同仁先刷卡買備品 | 員工自己 | 員工自助 `hr.rueisiang.com` 的「報帳」頁（正式員工從「工作」進去，支援人員在導覽上） | 會計審核，公司還錢給員工 |
| 公司直接付 | 跟廠商進貨、月結請款 | 會計 | 會計系統 | 會計記付款，沒有人要拿回錢 |

兩種放在同一張表，用 `payer_kind` 分。報表、匯出、帳期都只看一張表，不會有兩套。

支援人員也可以報公帳，兩種發放方式都能選（見第 3 節「支援人員」）。

### 每張支出單的內容

| 欄位 | 說明 |
|---|---|
| 消費日期 | 台北的日期 `YYYY-MM-DD`，決定落在哪個帳期 |
| 金額 | 分（`amount_minor`），跟薪資同單位 |
| 類別 | 進貨、備品、交通、餐費⋯，由會計維護的清單，不是科目表 |
| 店別 | 選填，指向既有的 `scopes`；給會計登記公司支出時用，員工報帳的表單不問 |
| 發票號碼、賣方統編 | 發票號碼用來抓重複報帳 |
| 用途說明 | 文字 |
| 單據照片 | 最多 5 張；收據（沒有發票號碼）必附，因為照片是唯一的憑證，有發票號碼時選填，存在既有的私有 R2 bucket `UPLOADS`（員工大頭貼也在那裡），只能經過有權限的 API 讀 |

發票號碼欄位旁有掃描鈕：拍電子發票證明聯左側的 QR code，帶入發票號碼、日期、含稅總計與賣方統編
（`apps/hr/src/routes/hr/invoice-qr.ts`），這張照片不會變成單據。另外加單據照片時也會順手讀，但只填空白的欄位。
手開發票與收據沒有 QR code，照舊手填。

## 3. 報公帳

### 流程

```text
員工送出 ─→ 待審 ─┬→ 核准・直接撥款 ─→ 會計標記已撥款 ─→ 已付款
                   ├→ 核准・併入月薪 ─→ 該月薪資結帳 ──→ 已付款
                   └→ 退回（寫原因）
員工在待審前可以自己撤回
```

- **審核一關**，由有審核權限的人（「會計」角色）審。
- **發放方式在核准時選**，每張單可以不一樣：

| 發放方式 | 錢怎麼出去 | 什麼時候算付出去 |
|---|---|---|
| 直接撥款（預設，隨報隨銷） | 會計另外轉帳 | 會計標記已撥款、填撥款日 |
| 併入月薪 | 核准時在同一個 transaction 產生一筆「薪資加扣項」 | 那個月的薪資結帳時 |

### 併入月薪

走既有的薪資加扣項（`hr_payroll_adjustments`），不另做一套。它的限制一起帶過來：

- 加扣項綁在任職資料（`employment_id`）上。支援人員也有任職資料（`hr_employments.person_kind = 'worker'`），
  薪資計算也會把加扣項算進他們的薪資，所以員工與支援人員都能選；**已封存、沒有在職任職資料的人只能直接撥款**，
  畫面上直接不給選。
- 只能掛在還沒結帳的月份。核准當月已結帳就掛下個月，核准畫面寫出是哪個月。
- 支出單指向它產生的加扣項，外鍵 `RESTRICT`：HRIS 不能把加扣項刪掉，讓支出單變成孤兒。
- **從報帳產生的加扣項在 HRIS 唯讀。** 外鍵擋得住刪除、擋不住修改，而 HRIS 本來就能改加扣項
  （`updateHrPayrollAdjustment`）；改了金額就跟支出單對不上。所以加扣項要記得自己是從哪張支出單來的，
  HRIS 的修改與刪除遇到這種加扣項一律拒絕，畫面上顯示「來自報帳，請由會計退回」。
- 要改金額就由會計退回支出單，同一個 transaction 移除對應的加扣項；薪資已結帳就不能退回，只能沖銷。
- 項目名稱寫「代墊款」：它是還員工的錢，不是薪資所得，薪資袋上要看得出來。

### 要處理的狀態

- **自己的單不能自己審**，跟「不能調整自己的角色與權限」同一個道理。只有一位會計時，會計自己的單由管理者審。
- 已核准的不能改；已付款的不能退回，只能另開一筆負數的沖銷。
- 同一個發票號碼已經報過：送件時提醒員工，審核時明顯標給會計看；不直接擋，因為一張發票可能拆給兩個人報。
- 送件人離職或停權：已送出的照常審、照常撥款；不能再送新的。
- 連按兩次送出只產生一張。
- 退回之後結案；員工可以「複製成新單」修改再送，舊的留著當紀錄。

### 支援人員

員工自助對支援人員只開「打卡」與「薪資」兩項，通知也關掉（`apps/hr/src/routes/hr/HrLayout.tsx` 依
`hrSelfServiceKind === "worker"` 過濾），API 也只放行那兩類。報帳不會自動出現在他們的畫面上，要明確做三件事：

1. 支援人員的導覽加上「報帳」，成為第三項。
2. 報帳的 API 放行支援人員，其他申請入口仍然不放行。
3. 核准、退回、撥款的通知也送給支援人員；只開報帳相關的通知，不開其他種類。

## 4. 權限

會計用自己的 `accounting:<資源>:<動作>`：

| 鍵值 | 給誰 |
|---|---|
| `accounting:expense:review` | 「會計」角色：審核報公帳、標記撥款 |
| `accounting:expense:write` | 「會計」角色：登記公司直接付的支出（第二批才加） |
| `accounting:expense:read` | 「會計」角色、老闆：看所有支出與匯出 |
| `accounting:category:write` | 「會計」角色：維護支出類別 |

「會計」角色由管理者在角色管理自己開：非管理者的角色範本只在系統第一次初始化時建立，正式環境不會自動多一個。

**送件不是權限**：跟請假一樣，能登入員工自助的人就能送自己的單，API 只讓他看自己的。
支援人員例外，要另外放行，見第 3 節。

**不要照抄 HRIS 薪資頁**的 `isHrAdministrator`（要求整個平台的「管理者」角色）。照抄的話，會計就得拿到
全平台的管理權限，連客戶、倉儲與權限設定都改得動。

## 5. 資料層的約束

- 時間照 [`database-conventions.md`](./database-conventions.md)；帳期用台北的日期切。
- 金額存分（`_minor`）。報表的出金存元，讀進會計時乘 100。
- 會計表的外鍵一律 `ON DELETE RESTRICT`。既有的表有 27 個 CASCADE（父表包含 `users`、`items`、`report_runs`），
  支出單不能因為刪了一個使用者或店別就跟著消失。
- 之後做帳期結帳時，已結帳的帳期用 trigger 擋修改，作法照薪資結算的守門 trigger。

### 會計之後會讀的既有資料

| 來源 | 現有的表 | 在內帳裡是什麼 | 缺口 |
|---|---|---|---|
| 每日出金 | `report_payout_daily` | 收入 | 只有一個金額欄位，手續費與退款沒拆開 |
| 商品銷售 | `report_item_sales_monthly` 等 | 營收明細 | 以月為單位 |
| 薪資 | `hr_payroll_runs`（`closed`）、`hr_payslips` | 薪資支出 | 只有結帳後的批次能用 |

會計只讀這些表，不回寫；唯一的例外是併入月薪時產生的薪資加扣項。

## 6. 分批

| 批次 | 內容 | 做完能做什麼 |
|---|---|---|
| **第一批：報公帳** | 支出表與類別表；員工自助的報帳表單與我的報帳（含支援人員的導覽與 API 放行）；會計系統的入口、待審清單、核准（選發放方式）、退回、標記撥款；從報帳產生的加扣項在 HRIS 唯讀；類別管理；權限 | 同仁可以在手機上報帳，會計在平台上審、撥款 |
| 第二批：公司支出與匯出 | 會計登記公司直接付的支出；支出列表（月份、店別、類別篩選）；匯出 Excel | 所有有發票的支出都在平台上，可以交給事務所 |
| 第三批：月報與結帳 | 每月、每店的收入（出金）減支出（含薪資）；帳期結帳與鎖帳 | 看得到每家店每個月賺多少 |
| 之後 | 逐項商品成本與毛利 | 看得到每一種商品賺多少 |

第一批先做報公帳，因為它的規則最清楚、牽涉的人最多，而且員工自助的表單、照片上傳、審核流程都有現成的可以照著做。
