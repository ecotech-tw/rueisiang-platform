# 執行 PRD：HR 員工設定

## 1. 目的

HR 員工不是另一套帳號，而是既有平台使用者（`users`）的人事延伸。HR 管理者從既有使用者選擇帳號，建立員工關聯與第一段任職資料。

```text
users 1 ─── 0..1 hr_employees 1 ─── N hr_employments
```

- `users` 是姓名、Email 與帳號狀態的唯一來源。
- `hr_employees` 保存員工編號、主管等員工層級資料。
- `hr_employments` 保存每一段任職／復職期間。
- 所有薪資、出勤、假勤與獎金資料應關聯 `employmentId`，不能只關聯 user。

## 2. 核心產品決策

1. 待啟用的 User 可以先指派為員工。
2. 主管不在第一次指派時設定，建立員工後從員工列表的「管理」入口設定。
3. 第一次任職必須設定出勤方式，預設為「一般辦公」。
4. 員工編號由 HR 手動輸入，且全平台唯一。
5. 所有員工都可以指定一個或多個辦公位置；辦公位置指派集中在「員工管理」，排班只負責每日工作地點安排。

## 3. 本功能範圍

### 包含

- 從既有 User 候選清單指派員工。
- 建立第一段任職紀錄。
- 設定出勤方式。
- 查看與搜尋員工。
- 查看員工內頁。
- 設定主管。
- 新增任職／復職。
- 結束任職。

### 不包含

建立員工時不設定：

- 薪資與勞健保
- 營運據點歸屬
- 辦公位置
- 排班
- 獎金
- 請假與加班

這些資料在員工建立後，從各自的 HR 管理頁設定；辦公地點與每日地點安排統一在「排班管理」設定。

## 4. 導覽與頁面

```text
HRIS
└─ 員工管理
   ├─ 員工列表
   └─ 員工內頁
```

### 員工列表

- 頁面標題：員工列表
- 右上角主要操作：指派員工
- 搜尋：姓名、員工編號、Email
- 篩選：帳號狀態
  - 啟用中
  - 待啟用
  - 已停用
- 欄位：員工編號、姓名、Email、帳號狀態、任職狀態
- 支援排序與分頁。
- 點擊整列進入員工內頁；列上的「管理」入口開啟員工與任職異動 Dialog，不進入內頁操作。

帳號狀態與任職狀態必須分開顯示：

| 狀態 | 來源／判斷方式 |
|---|---|
| 帳號狀態 | `users.status` |
| 任職狀態 | 依 `hr_employments` 與目前日期計算 |

停用帳號不等於刪除員工，也不等於刪除任職歷史。

## 5. 指派員工 Dialog

### 欄位

| 欄位 | 必填 | 規則 |
|---|---:|---|
| 使用者 | 是 | 從尚未成為員工的 User 選擇 |
| 員工編號 | 是 | 手動輸入，1～40 字元，全平台唯一 |
| 到職日 | 是 | 第一段任職起日 |
| 年資認列日 | 是 | 預設等於到職日，不得晚於到職日 |
| 出勤方式 | 是 | 一般辦公／排班，預設一般辦公 |

使用者選項顯示：

```text
王小明（wang@example.com）
```

姓名與 Email 只讀，不複製到 `hr_employees`。

### User 候選條件

- `users.status` 為 `active` 或 `invited`。
- 尚未存在 `hr_employees` 關聯。
- 不提供在此建立新 User 的功能。
- 沒有候選人時顯示前往使用者管理邀請帳號的提示。

### 建立操作

指派員工必須以同一個原子操作建立：

1. `hr_employees`
2. `hr_employments`
3. `hr_employment_attendance_settings`

任何一步失敗，整次操作不得留下半套員工資料。

建立成功後導向：

```text
/hr/employees/:userId
```

## 6. 員工內頁

### 基本資料

顯示：

- 姓名：來自 `users`
- Email：來自 `users`
- 帳號狀態：來自 `users`
- 員工編號：來自 `hr_employees`
- 主管：可顯示尚未設定

### 任職資料

每一段任職顯示：

- 到職日
- 不再任職首日
- 年資認列日
- 出勤方式

員工內頁只呈現資料，不提供資料異動按鈕。員工編號、主管、任職／復職、結束任職與營運櫃點歸屬，從員工列表列上的「管理」入口開啟 Dialog；辦公位置與出勤方式從「出勤／出勤範圍管理」維護，薪資與勞健保從各自管理頁維護。

員工內頁採互斥 Accordion；一次只展開一個資料區塊。

### 辦公地點摘要

所有員工不論出勤方式，都可以指定一個或多個有效辦公位置；實際新增、移除與日期設定統一在「出勤／出勤範圍管理」操作。

員工內頁只顯示：

- 目前有效辦公地點。
- 各地點生效期間。
- 前往「出勤／出勤範圍管理」的入口（唯讀導引）。

一般辦公員工以有效辦公地點作為可打卡地點範圍。每日工作地點若需要依日期變更，使用「排班管理／排班月曆」設定。

## 7. 任職與復職規則

### 結束任職

`endedOn` 表示「不再任職的第一天」，採半開區間 `[hiredOn, endedOn)`。

例如：

```text
hiredOn: 2026-01-01
endedOn: 2026-08-01
```

最後工作日為 2026-07-31。

結束任職前，必須先結束超出離職日期的：

- 營運據點歸屬
- 辦公位置指派

### 復職

不可把舊任職的 `endedOn` 清空。復職必須新增另一筆 `hr_employments`。

```text
同一 User
  └─ 同一 hr_employee
       ├─ employment A：已結束
       └─ employment B：復職後新任職
```

同一 User 的任職期間不可重疊。

## 8. 主管設定

主管從既有 HR 員工中選擇：

- 必須是啟用中的 User。
- 不可設定自己為主管。
- 可清除主管。
- 主管設定保存於 `hr_employees.supervisor_user_id`。
- 補打卡與其他申請可使用該主管作為預設審核者。

## 9. 權限

| 操作 | 權限 |
|---|---|
| 查看員工列表與基本資料 | `hr:employee:read` |
| 指派員工 | `hr:employee:write` |
| 編輯員工編號 | `hr:employee:write` |
| 設定主管 | `hr:employee:write` |
| 新增任職／復職 | `hr:employee:write` |
| 結束任職 | `hr:employee:write` |

薪資、勞健保、請假與打卡明細另依敏感資料權限限制，不因可以查看員工基本資料而自動開放。

## 10. 失敗狀態

UI 必須能顯示後端明確錯誤：

- 使用者已經是員工。
- 員工編號已被使用。
- 使用者不存在或帳號狀態不允許。
- 到職日與年資認列日不合法。
- 任職期間重疊。
- 資料已被其他人修改，要求重新整理。
- 沒有符合條件的 User 候選人。

員工資料與任職資料不提供物理刪除按鈕。

## 11. UI 設計要求

- 列表使用 `.page.fills`、`.panel.grows`。
- 搜尋與篩選使用 compact toolbar。
- 表格使用既有 `.data-table` 與 sticky header。
- 操作集中在 Dialog，不在表格列內展開表單。
- 手機版使用 `data-label` 呈現表格欄位名稱。
- 姓名／Email 等 User 欄位不可在 HR 表單重複編輯。
- 重要異動需保留 revision 與操作紀錄。

## 12. 驗收條件

- 可以從 active 或 invited User 建立員工。
- 同一 User 不可重複指派。
- 員工編號不可重複。
- 姓名與 Email 永遠顯示 User 的最新資料。
- 建立員工會同時產生第一段任職與出勤設定。
- 預設出勤方式為一般辦公，但可在建立時選擇排班。
- 待啟用 User 可被建立，但尚未啟用前不應進入正常薪資計算。
- 停用 User 不會刪除員工與歷史任職。
- 離職保留舊任職，復職建立新任職。
- 主管不可指定自己。
- 任職期間不可重疊。
- 任一建立步驟失敗時，不留下半套資料。
