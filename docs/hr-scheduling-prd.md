# 執行 PRD：排班管理與工作地點快速排班

## 1. 目的

排班由班別管理與排班月曆組成。班別定義實際上下班時段與計薪工時，排班月曆記錄員工在特定日期到哪個據點、使用哪個班別，以及休假日。

> 某位員工／支援人員，在某一天工作的營運據點。

上下班時段、計薪工時與休息時間由排班所選的班別提供，並在發布排班時保存快照，供出勤異常判斷與後續薪資作業參考；辦公位置只負責員工授權的地理打卡範圍。

主要操作是：

```text
選月份 → （選用）篩選據點 → 快速排班或點日期 → 儲存
```

## 2. 固定工作地點與每日排班

兩種資料分開：

### 員工的辦公位置指派

在「出勤／出勤範圍管理」設定，所有員工都可以指定一個或多個辦公位置。頁面以員工為操作主體，保存同一份有效期間資料。

```text
王小明
├─ 台北店（有效）
└─ 桃園店（有效）
```

用途：

- 一般辦公員工可在有效辦公地點打卡。
- 出勤範圍管理是打卡授權的唯一來源；排班據點是每日工作安排，不會改變員工可打卡位置。
- 排班制員工可設定每月固定休假天數，例如 8 天或 10 天；排班發布時檢查本月休假數與班別完整性。
- 上下班時段、休息時間與計薪工時由班別管理提供，不由辦公位置推導。
- 每個指派保存生效日與失效日。

### 辦公位置指派資料（由出勤範圍管理維護）

預設畫面以員工為操作主體：

```text
選擇員工：[搜尋員工              ▾]
辦公位置：☑ 台北店  ☑ 桃園店  ☐ 新竹店
排班規則：每月休假 10 天
[儲存]
```

- 新增與移除都保存生效日／失效日，不物理刪除歷史指派。
- 若移除的辦公位置仍有相關排班，排班資料仍保留；需要調整時另到排班月曆處理。
- 已發生的出勤、排班與薪資歷史不受後續地點指派變更影響。

### 班別管理

每個營運據點可以建立多個班別，同一據點可同時存在早班、晚班與假日班：

```text
S1 早班：10:00～19:30，計薪 8.5 小時
S1 晚班：13:00～21:30，計薪 7.5 小時
S1 假日晚班：13:00～22:00，計薪 8 小時
```

每個班別可以設定：

- 班別名稱
- 開始時間與結束時間
- 休息時間
- 計薪工時
- 啟用狀態與版本

平日與假日工作時數不同時，建立不同班別，排班時依日期選擇適用班別。
- 排班發布時，若員工設定每月休假天數，系統檢查該月有效任職日中未排班的天數必須符合約定；不在目前階段實作勞基法週期檢核。
- 第一版不設定跨午夜與多段休息區段；班別只保存單一休息分鐘數。
- 實際打卡超出時段與容許範圍仍允許保存，但列為出勤異常供 HR 檢查。
- 提前、遲到、早退與超時只作為出勤提示，不自動扣薪、不自動增加薪資，也不取代核准的加班申請。

### 每日工作地點安排

在排班管理的排班月曆設定，適合不同日期到不同據點工作的情況。排班是管理者的人力安排參考，不是打卡的必要條件。

```text
王小明
├─ 2026-08-05：台北店
├─ 2026-08-06：桃園店
└─ 2026-08-07：台北店
```

排班不覆蓋員工的固定地點指派；它是特定日期的工作地點安排。

## 3. 導覽

```text
HRIS
└─ 排班管理
   └─ 排班月曆
```

班別管理位於排班選單下，依營運據點維護班別；不建立正式員工排班與支援排班兩套頁面。

## 4. 頁面 UI

### Header

- 標題：排班管理
- 主要操作：儲存（成功後直接發布）
- 次要操作：鎖定／開鎖
- 顯示目前月份版本狀態：未建立、已發布、已鎖定
- 有變更時顯示「尚有未發布變更」

### 工具列

```text
[上個月]       2026 年 8 月       [下個月]
工作地點：[台北店                         ▾]
焦點人員：[搜尋並選擇員工                 ▾]
```

- 可用「全部營運據點」檢視；實際新增排班時，仍須選定一個營運據點與班別。
- 新增排班對話框一次選一人；快速排班固定一位人員後點擊多個日期。
- 焦點人員可選正式員工或臨時支援人員。
- 只列出在該月份具有有效任職或有效支援資格的人員。
- 排班的營運據點與班別由管理者依每日人力安排選擇；排班不授予或限制員工的打卡位置，員工仍只能在「出勤／出勤範圍管理」已授權的辦公位置打卡。

### 焦點人員摘要

```text
王小明・正式員工
本月已安排 12 天　未發布變更：新增 3 天、移除 1 天
```

## 5. 點日期快速排班

### 空白日期

```text
工作地點：台北店
焦點人員：王小明
→ 點擊 8/5
→ 8/5 顯示「台北店」
→ 標記為未發布變更
```

### 再次點擊同一日期

```text
已有台北店 → 移除 8/5 的工作地點排班
```

### 日期已有其他工作地點

同一人同一天可以有一個或多個已指派的工作地點。排班只記錄地點安排，不記錄先後時間，因此新增不同地點時不產生班別衝突。

再次點擊同一個已排地點時移除該地點；點擊其他地點時新增該地點。相同人員、日期與地點不可重複建立。

## 6. 月曆顯示

- 顯示月份日期格。
- 焦點人員的工作地點以主要色調顯示。
- 其他人員顯示淡色摘要或當日人數，讓管理者掌握人力分布。
- 日期格顯示日期、焦點人員工作地點與必要的人數摘要。
- 支援人員使用「支援」標籤。
- 已鎖定月份不可新增、移除或變更。

## 8. 儲存與發布

```text
點擊多個日期
→ 月曆顯示未發布變更
→ HR 檢查整月
→ 儲存（直接發布）
→ 後端驗證並原子寫入
```

- 點日期不立即寫入資料庫。
- 「儲存」一次提交整個月份結果並直接發布。
- 沒有該月份版本時建立第一版；已有版本時使用 revision 更新。
- 開鎖後修改原本版本，不建立新版本。
- 任一筆資料衝突，整次儲存失敗，不留下部分發布結果。
- 儲存成功後清除未發布標記並重新載入版本。

## 9. 出勤與薪資關係

- 有沒有已發布工作地點排班都可以打卡；排班只作為管理者與薪資作業的參考。
- 員工可以在所有有效辦公地點打卡，不限於當日排班地點。
- 若特定日期有工作地點排班，該地點作為該日的工作安排參考，不作為打卡權限限制。
- 打卡紀錄可以依實際打卡地點的上下班時段驗證，超出時段仍打卡成功，但建立出勤異常。
- 實際打卡地點與排班地點不同時，打卡仍成功，但建立薪資結算異常；結帳前可修正排班後重新試算。
- 打卡時間與工作地點時段不一致時只建立出勤提醒，不影響薪資結果。
- 工作地點排班不代表已打卡，也不代表加班核准。
- 月薪制員工不依排班日數計算月薪。
- 日薪制員工依已發布工作地點排班日期計算；沒有該日排班就不計日薪。
- 時薪員工在每月結束時由 HR 登記實際工作日期與時數；時數以 0.5 小時為單位，不由排班或打卡自動產生薪資時數。
- 支援人員依已發布工作地點日期計算支援薪資。
- 班別時間只供出勤異常與排班計薪參考；加班仍需另行申請，並由薪資引擎獨立計算當日加班費。

## 10. 支援人員

支援人員可以排班，並使用與正式員工相同的「焦點人員 → 日期」操作。支援人員主檔的新增、編輯與停用入口位於「員工／支援人員」，不是排班月曆；排班月曆只負責消費有效的支援人員名單。

- 支援人員不屬於正式員工，不建立 `user`、任職或主管關聯。
- 正式員工使用 `employmentId`。
- 支援人員使用 `workerId`。
- UI 必須清楚標示人員類型。
- 支援人員排班日數作為目前支援薪資計算依據。

## 11. 驗證與衝突

點擊日期時前端先做已知檢查，儲存時後端必須再次驗證：

- 工作地點是有效的 store scope。
- 人員在該日期具有有效任職或支援資格。
- 班別已掛在該營運據點，且工時快照符合班別時長。
- 同一人員、日期與工作地點沒有重複資料。
- 月份沒有被鎖定。
- revision 沒有過期。

錯誤訊息要指出具體人員、日期與工作地點：

```text
王小明在 2026-08-05 已經有重疊的台北店班別，不能重複新增。
```

## 12. 權限

| 操作 | 權限 |
|---|---|
| 查看工作地點月曆 | `hr:schedule:read` |
| 新增、移除、儲存發布 | `hr:schedule:write` |
| 鎖定／開鎖 | `hr:schedule:write` |
| 指派員工辦公地點 | `hr:employee:write` |

## 13. 核心產品決策

1. 支援人員可以排班。
2. 班別由據點管理；同一人同一天可以安排一個或多個不重疊班別。
3. 可以檢視全部據點，但新增排班前必須選定一個工作地點與班別。
4. 開鎖後修改原版本，不建立新版本。
5. 沒有已發布班表時不禁止打卡。
6. 不設定跨午夜班別與休息區段。
7. 一般辦公員工也可以指定一個或多個辦公地點，所有有效辦公地點都可以打卡。
8. 沒有排班也可以打卡，排班只作為參考。
9. 時薪每月底手動登記實際工作日期與時數，最小單位為 0.5 小時。
10. 實際打卡地點與排班地點不一致時，列入薪資結算異常；修正排班後重新試算。
11. 手動補打卡需要主管核准。
12. 薪資結帳後發現錯誤，建立薪資調整，不回頭修改已結帳結果。
